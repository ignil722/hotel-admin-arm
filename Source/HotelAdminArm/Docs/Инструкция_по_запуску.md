# Запуск и работа с гостиницей

Проект Терехова С. М., ПИНз-123. WinForms .NET 8, локальная SQLite, русский интерфейс.

## Готовая сборка

Откройте `Published/HotelAdminArm.exe` в корне проекта. Потребуется .NET Desktop Runtime 8 для Windows. Сохраняйте весь каталог рядом с exe.

В Visual Studio откройте `Source/HotelAdminArm.sln`, дождитесь восстановления пакетов, выберите проект HotelAdminArm и нажмите F5. Команды из корня проекта:

```powershell
dotnet build Source/HotelAdminArm.sln -c Release
dotnet run --project Source/HotelAdminArm -c Release
dotnet run --project Source/HotelAdminArm.Tests -c Release
```

## Рабочая база

Файл `%LOCALAPPDATA%\HotelAdminArm\hotel.db` хранится отдельно от сборки. Новая база получает согласованный демонстрационный набор. Пустая таблица номеров в существующей базе не приводит к повторному заполнению.

Перед обновлением старой схемы программа сохраняет SQLite-копию в `Backups`. Версия схемы — 6. Фотографии и примечания не заменяются оформлением. Исторические платежи не пересчитываются. Вкладка «Контроль и копии» показывает просроченные проживания, истёкшие брони, приблизительные старые тарифы и архив без подтверждённого расчёта. Проверьте эти записи по фактическим данным гостиницы.

Для отдельной демо-базы:

```powershell
.\Published\HotelAdminArm.exe --database "$env:TEMP\hotel-demo.db"
```

## Основной сценарий

1. Создайте карточку гостя. Если дата рождения неизвестна, снимите флажок у даты.
2. На вкладке «Бронирование» выберите даты, тип и вместимость, найдите номер и начните новую бронь. Можно начать её двойным щелчком по свободному дню календаря.
3. Сохраните бронь и подтвердите её. Для редактирования выберите запись, для новой записи нажмите «Новая бронь». Статус «Заселен» устанавливается автоматически при заезде.
4. Во вкладке «Заселение и архив» оформите сегодняшний заезд по действующей подтверждённой брони либо без брони с проверкой доступности. Ранний заезд требует предварительно изменить даты брони.
5. Добавьте остальных проживающих через кнопку «Проживающие», при необходимости продлите срок или переселите гостей. Вместимость проверяется, прежние периоды и тарифы сохраняются.
6. Добавьте услуги к активному проживанию. Стоимость заказа сохраняется при добавлении.
7. Выберите проживание или несколько строк оплаты. Откройте расчёт: проверьте гостей, комнаты, дни, тарифы и услуги, затем выберите плательщика и способ в этом же окне. Подтвердите оплату и выезд. Повторная оплата отклоняется.
8. Откройте детали платежа или счёт из архива и используйте предпросмотр/печать. Для нулевого счёта создаётся итоговый расчёт и архив, денежный платёж не создаётся.

Статус ремонта и активность номера редактируются отдельно; занятость рассчитывается из данных. Просроченный выезд не освобождает комнату. Пересечение периодов запрещено; соседние периоды допускаются. Цена начисляется за весь номер в целых копейках, минимум одни сутки на проживание.

## Копии и восстановление

В «Контроль и копии» нажмите «Резервная копия» и выберите новое имя файла. Для восстановления закройте другие экземпляры, выберите проверенную копию и подтвердите восстановление. До замены сохраняется текущая база. Ошибочный файл не заменяет рабочую базу. Если запуск прерван ошибкой базы, программа предлагает выбрать резервную копию. Повреждённый файл, который нельзя открыть через SQLite, сохраняется вместе с журналами как damaged-* в Backups; затем возвращается проверенная копия.

При конфликте миграции оригинал сохраняется, а сообщение и текстовый отчёт в `Backups` перечисляют ID для сверки. Записи автоматически не объединяются. Сначала исправьте конфликт в отдельной копии по достоверным данным, затем восстановите проверенную копию.

## Поиск и обновление

Быстрый поиск есть в номерах, гостях и бронях. Календарь и поиск используют одни правила. После операций связанные вкладки обновляются. Смена дня и повторная активация окна также обновляют данные; часы обновляются каждые 30 секунд. На небольшом экране таблицы и формы прокручиваются.

Авансы, частичная оплата, возвраты и банковская интеграция не реализованы. Выбор карты или перевода только регистрирует способ расчёта.
